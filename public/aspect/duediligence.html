04

הפצה לצדדים שלישיים

רכיבי צד-שרת

אינם מופצים ללקוחות. השרת מופעל כשירות ענן (SaaS) על גבי Google Cloud Run. הלקוחות ניגשים לשירות דרך API בלבד ואינם מקבלים עותק של הקוד או של רכיבי הקוד הפתוח.

לפיכך מדובר במודל שימוש מסוג שירות על גבי הרשת (network service / SaaS) ולא בהפצה (distribution) של התוכנה.

בהתאם לכך, מרבית חובות ה-attribution הקשורות להפצת תוכנה ברישיונות כגון MIT ו-Apache-2.0 אינן חלות בפועל. עם זאת, קבצי הרישיון המקוריים נשמרים במלואם בתוך תיקיית node_modules.

רכיבי צד-לקוח

מועברים בעקיפין. קוד ה-JavaScript הבנוי (bundled & minified) כולל את קוד הרכיבים react, react-dom, react-router-dom, react-markdown, remark-gfm, html2canvas, prism-react-renderer ו-react-image-crop. קבצים אלו מוגשים לדפדפן המשתמש הקצה דרך Firebase Hosting.

כל רכיבים אלו מורשים תחת רישיונות MIT / ISC שמתירים הפצה ללא מגבלות, בתנאי שהודעות הרישיון נשמרות.

רכיבי Build ו-Dev

לא מופצים כלל. כלים כמו vite, eslint, typescript, drizzle-kit ו-@types/* משמשים בסביבת הפיתוח בלבד ואינם חלק מהמוצר המסופק ללקוחות.

04A

שירותי צד שלישי (Third-Party Services)

בנוסף לרכיבי קוד פתוח, המערכת משתמשת במספר שירותי ענן חיצוניים הנצרכים באמצעות ספריות SDK רשמיות.

שירותים אלו אינם רכיבי קוד פתוח אלא שירותים מסחריים הכפופים לתנאי השימוש של הספקים.

השירותים העיקריים

  • OpenAI API
  • Anthropic Claude API
  • Google Gemini API
  • Google Cloud Storage
  • Google Sheets / Google Drive APIs

השימוש בשירותים אלו נעשה דרך ספריות ה-SDK הרשמיות בלבד, ללא הכללת קוד מקור של השירותים עצמם במערכת.

05

שינויים/תיקונים ברכיבי קוד פתוח

Aspect לא שינתה ולא תיקנה (modified / forked) אף רכיב קוד פתוח.

כל הרכיבים מותקנים ישירות מ-npm registry בגרסאותיהם המקוריות, ללא patches, forks או שינויים:

  • כל הרכיבים מוגדרים ב-package.json עם גרסאות סמנטיות סטנדרטיות (^ / ~)
  • לא קיימים קבצי patch (אין תיקיית patches/)
  • לא קיימים forks או הפניות ל-git repositories מותאמים
  • תיקיית node_modules נוצרת מחדש ע״י npm install מהרגיסטרי הציבורי

כיוון שלא בוצעו שינויים — אין חובה לפרסם קוד מקור או שינויים תחת אף רישיון.

06

עמידה בחובות רישיונות קוד פתוח

הודעות זכויות יוצרים ו-Attribution

  • כל רכיב קוד פתוח בתיקיית node_modules כולל את קובץ ה-LICENSE המקורי שלו
  • קבצי הרישיון נשמרים כחלק מהתקנת npm ולא נמחקים או שונו

צד שרת

השרת מופעל כשירות SaaS ולא מופץ כתוכנה. מרבית חובות ה-attribution הקשורות להפצת תוכנה ברישיונות כגון MIT ו-Apache-2.0 אינן חלות בפועל. עם זאת, קבצי הרישיון המקוריים נשמרים במלואם בתוך תיקיית node_modules.

צד לקוח

ה-bundle שנוצר ע״י Vite כולל קוד מינימלי (minified). רישיונות MIT ו-ISC דורשים שמירת הודעת הרישיון בכל העותקים או חלקים מהותיים מהתוכנה.

ניתן להוסיף לקוד הלקוח קובץ THIRD_PARTY_LICENSES.txt שיכלול את הודעות הרישוי של כל הספריות הכלולות ב-bundle של הקליינט. קובץ כזה ניתן להפיק אוטומטית בתהליך הבנייה באמצעות תוסף כגון rollup-plugin-license.

07

רכיבי Copyleft

לא נעשה שימוש ברכיבי Copyleft (GPL / LGPL / AGPL) כלל.

כל רכיבי הקוד הפתוח בפרויקט מורשים תחת רישיונות מתירניים (permissive) בלבד:

  • MIT (34 רכיבים) — מתירני לחלוטין
  • Apache-2.0 (7 רכיבים) — מתירני, דורש attribution ו-NOTICE
  • BSD-2-Clause (1 רכיב) — מתירני
  • ISC (1 רכיב) — מתירני, דומה ל-MIT
  • PostgreSQL License (1 רכיב) — מתירני

אין סיכון לחשיפה כפויה של קוד מקור קנייני של Aspect, ואין מגבלות על מסחור הנובעות מרישיונות הקוד הפתוח בשימוש.

בהתאם לכך, לא קיימת דרישה לחשיפת קוד מקור קנייני של Aspect ואין מגבלות רישוי העלולות להשפיע על מסחור המערכת.

08

תהליך וכלי ניהול קוד פתוח (SCA)

ניהול הקוד הפתוח מתבצע במספר שכבות:

  • npm audit — הכלי המובנה ב-npm זמין לסריקת פגיעויות אבטחה בתלויות. בדיקות פגיעויות מבוצעות באופן תקופתי באמצעות npm audit. נכון למועד הכנת מסמך זה, לא זוהו פגיעויות אבטחה קריטיות בתלויות הריצה של המערכת.
  • בקרת גרסאות — כל התלויות מנוהלות דרך package.json עם version pinning
  • lock files — קבצי package-lock.json מבטיחים עקביות בין סביבות
  • אישור הכנסת רכיב חדש — מתבצע ע״י צוות הפיתוח כחלק מתהליך ה-code review
  • SBOM — הפקת Software Bill of Materials אוטומטי מתוך קובץ package-lock.json באמצעות כלים כגון CycloneDX לצורך שקיפות מלאה של רכיבי הקוד הפתוח
